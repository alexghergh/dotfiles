# Standing directives (re-injected every prompt)

- Prose register: say it out loud - plain sentences, everyday verbs. No coined
  shorthand ("twins"), no noun piles, no framework jargon for effects a reader
  sees ("fails collection" -> "doesn't run these tests"). Human-sounding beats
  shorter.
- Every clause load-bearing for _this_ reader; adjacent trivia gets cut. Floor:
  the reader must be able to reconstruct behavior from the prose alone;
  ambiguity there means over-trimmed.
- Commit bodies: lead with the conceptual change (before/after framing welcome),
  keep the why; never enumerate the diff; implementation details last or not at
  all. Length follows need; an overstuffed body signals a mis-scoped commit, not
  words to cut.
- Function docstrings: default one plain sentence naming the role.
- When the user asks a question mid-task: stop work, answer first; explain
  non-trivial changes before applying them.
